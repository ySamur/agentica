# agentica

Лендинг о разработке с ИИ-агентами, Google-вход через Supabase, профиль и закрытый контент. React + TypeScript (strict) + Vite + React Router.

## Запуск

```sh
npm install
npm run dev
```

По умолчанию приложение доступно на http://localhost:3000. Если порт занят, Vite автоматически выбирает следующий свободный: откройте адрес из строки `Local` в терминале. Сервер слушает только localhost; для доступа из локальной сети используйте `npm run dev:lan`. В Windows PowerShell с ограничением запуска скриптов используйте `npm.cmd` вместо `npm`.

```sh
npm run typecheck
npm run lint
npm run build
npm run preview
```

## Проверки в браузере

```sh
npm test
npm run test:security
```

Playwright проверяет лендинг и авторизацию в установленном Google Chrome на desktop и mobile. Тесты запускают собственные серверы на **4317 и 4318**, с отдельными кэшами Vite и фиктивными публичными настройками; существующий сервер на 3000 не используется. Эти два порта должны быть свободны. Все запросы авторизации перехватываются тестовыми фикстурами: реальные аккаунты и секреты не нужны. Снимки экрана сохраняются в `.local/screenshots`, трассы ошибок — в `test-results`.

`test:security` выполняет миграцию в локальном PostgreSQL-движке PGlite и проверяет права чтения, запрет записи и RLS. Это проверка SQL, а не подключения к облачному Supabase.

## Структура

- `src/app` — точка сборки приложения.
- `src/pages/landing` — главная публичная страница.
- `src/pages/auth`, `src/pages/settings`, `src/pages/content` — вход, профиль и контент.
- `src/components` — общие компоненты и SVG-иконки.
- `src/features/auth` — сессия, меню аккаунта и защита маршрутов.
- `src/lib/supabase.ts` — единый клиент Supabase и типы данных.
- `src/features/workflow` — интерактивная демонстрация работы агентов.
- `src/features/starter` — окно с готовыми запросами и копированием.
- `src/styles.css` — адаптивные стили и поддержка reduced motion.
- `src/account.css` — оформление авторизации и личного пространства.
- `supabase/migrations` — SQL-миграция закрытого контента.

Лендинг работает без сервера и секретов. Схема агентов — интерактивная иллюстрация, она не запускает реальные модели. Основные кнопки открывают полезные шаблоны запросов. На странице также работают переключатель сравнения, FAQ и мобильное меню.

## Подключение Google и Supabase

Следуйте [пошаговой инструкции](docs/AUTH_SETUP.md): создайте проекты в своих аккаунтах, настройте Google OAuth, выполните SQL-миграцию и заполните `.env.local` по `.env.example`. До настройки публичный лендинг работает, а страница входа сообщает о временной недоступности. Секрет Google хранится только в настройках провайдера Supabase. Во фронтенд передаются URL проекта и Publishable key; секретные ключи и `service_role` запрещены.

| Маршрут | Назначение |
| --- | --- |
| `/` | Публичный лендинг |
| `/login` | Вход и регистрация одной кнопкой Google |
| `/auth/callback` | Автоматическое завершение OAuth PKCE через SDK |
| `/settings/profile` | Имя на сайте, email и аватар Google; требуется сессия |
| `/content` | Контент из Supabase, защищённый RLS; требуется сессия |

Имя сохраняется в `user_metadata.display_name`, не меняя аккаунт Google. Сессия сохраняется при перезагрузке; выход действует на текущую браузерную сессию и синхронизируется между вкладками. Контент не встроен в клиентский код: таблица разрешает чтение только вошедшим пользователям. При выходе или потере сессии закрытые страницы убираются из интерфейса.

Автотесты не подтверждают настройку реального Google-провайдера. Для завершения подключения пройдите ручную проверку входа и доступа к данным из инструкции. Размещение на домене, другие способы входа, загрузка аватара и удаление аккаунта остаются вне текущего этапа.

Шрифты Golos Text и IBM Plex Mono входят в сборку и обслуживаются вместе с приложением. Внешние запросы к сервисам шрифтов не требуются.
